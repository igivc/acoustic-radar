# Acoustic Radar

Приложение на C++20 для наблюдения резонансного отклика бокалов. Динамик излучает линейный chirp, микрофон принимает возбуждение и послезвучие, а программа накладывает спектры последовательных циклов на общую временную ось. При добавлении воды можно наблюдать изменение резонансных частот. Расстояние до объекта программа не измеряет.

## Подключение

Программа рассчитана на Linux/ALSA и Steinberg UR22C. Устройство выбирается по имени `UR22C` и поддержке минимум четырёх входных и двух выходных каналов. Выбор другого устройства через UI пока не предусмотрен.

| Подключение | Назначение |
| --- | --- |
| OUTPUT 1 → INPUT 1 | Электрическая петля синхронизации |
| OUTPUT 2 → динамик | Акустическое возбуждение |
| sE Electronics X1 S → INPUT 2 | Приём акустического сигнала; микрофону требуется +48 В |

В PortAudio используется interleaved Float32: четыре входа, два выхода, частота 48 кГц, блок callback 512 кадров. Один кадр содержит по одному одновременному отсчёту каждого канала. Детектор читает входной канал с индексом 0, спектральный анализатор — с индексом 1. Каналы с индексами 2 и 3 для спектрограммы не используются. Дополнительные входные каналы интерфейса могут содержать сигналы аппаратной маршрутизации.

## Сборка

Нужны компилятор с C++20, CMake 3.20+, Ninja, pkg-config и библиотеки разработки:

- SDL3 с CMake-пакетом `SDL3Config.cmake`;
- PortAudio с pkg-config модулем `portaudio-2.0`;
- FFTW3 с модулем `fftw3` (double precision).

```bash
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

Если SDL3 установлена в нестандартный каталог, укажите его через `CMAKE_PREFIX_PATH` или `SDL3_DIR`. Для библиотек, найденных через pkg-config, используйте соответствующий `PKG_CONFIG_PATH`. Вместо Ninja можно выбрать генератор `Unix Makefiles` в отдельном каталоге сборки.

## Запуск и управление

```bash
./build/acoustic_radar
```

Живой режим непрерывно генерирует звук и обновляет график до Escape или закрытия окна. Окно должно иметь фокус для управления клавиатурой.

| Клавиши | Действие |
| --- | --- |
| ↑ / ↓ | Сдвиг обеих границ chirp на ±100 Гц, ширина остаётся 1000 Гц |
| ← / → | Уменьшение / увеличение длительности chirp на 10 мс |
| Escape | Остановка и выход |

Начальные параметры: **1900–2900 Гц, 250 мс**. Нижняя граница регулируется от 100 до 19000 Гц, длительность — от 20 до 590 мс. Период между началами циклов фиксирован: **1000 мс**. Параметры показаны в заголовке окна.

Генератор принимает новые настройки с начала следующего цикла, чтобы не менять фазу текущего сигнала. Диапазон отображения меняется сразу; накопленные следы при перестройке частоты очищаются.

## Как читать спектрограмму

- **X:** время 0–1000 мс от начала синхромаркера, найденного корреляцией на INPUT 1. Это не время вызова callback и не момент отправки звука.
- **Y:** частота микрофонного сигнала INPUT 2 в выбранном диапазоне chirp.
- **Цвет:** частота от красного через оранжевый и жёлтый к белому у верхней границы диапазона.
- **Яркость:** амплитуда спектральной компоненты. Визуальный диапазон фиксирован: от −80 до −15 dBFS; уровень управляет прозрачностью наносимой ячейки.
- Вертикальная линия отмечает установленную длительность возбуждения. Правее неё можно наблюдать затухание отклика.

Каждый новый полный цикл накладывается поверх предыдущих. Перед его нанесением яркость истории уменьшается на **40%**, то есть сохраняется 60%. Затухание происходит один раз на полученный цикл, а не при каждой перерисовке окна. При отсутствии маркеров новые циклы не рисуются и история не затухает. При перестройке диапазона счётчик показанных циклов сбрасывается вместе с изображением.

Верхняя строка показывает параметры FFT, число нанесённых циклов и корреляцию последнего маркера. Корреляция характеризует сходство с эталоном, а не уровень микрофона.

## Сигналы и спектральный анализ

| Параметр | Значение |
| --- | --- |
| Частота дискретизации | 48000 Гц |
| Период цикла | 1000 мс / 48000 отсчётов |
| OUTPUT 1: синхромаркер | Chirp 8–12 кГц, 10 мс, окно Ханна, амплитуда 0,1 |
| OUTPUT 2: возбуждение | По умолчанию 1900–2900 Гц, 250 мс, амплитуда 0,5 |
| Огибающая возбуждения | Косинусные нарастание и спад по 10 мс |
| FFT | 4096 отсчётов, окно Ханна |
| Шаг окон | 1024 отсчёта / 21,33 мс, перекрытие 75% |
| Частотный шаг бинов | 11,71875 Гц |
| Длительность окна | 85,33 мс |

Оба выходных сигнала начинаются одновременно в начале цикла. После возбуждения правый выход молчит до следующего цикла.

Время измерения соответствует середине окна FFT. Используются только окна, полностью помещающиеся в цикл: нулевого дополнения на его границах нет. Поэтому график не заполняет крайние участки оси до 0 и 1000 мс. Частотный шаг бинов не равен способности разделить два близких резонанса: она также зависит от окна и длительности сигнала.

FFTW возвращает ненормированный комплексный спектр. Анализатор делит модуль на сумму окна и удваивает положительные частоты, кроме DC и Найквиста. Синус амплитуды 1 в центре бина даёт примерно 0 dBFS. Это амплитудный уровень, не спектральная плотность мощности. Для тишины установлен численный предел −200 dBFS.

## Обработка и потоки

```text
PortAudio callback
  ├─ генерация двух выходов
  └─ SPSC-кольцо четырёхканальных входных кадров
       ↓
ProcessingWorker (отдельный std::jthread)
  корреляция → полный цикл → STFT/FFTW
       ↓
Ограниченная очередь готовых спектров
       ↓
Основной поток SDL: накопительная текстура → окно
```

Callback не выполняет FFT, корреляцию, файловые операции и блокировки. SPSC-кольцо содержит 131072 кадра, около 2,73 с звука. Если оно заполнено, новые кадры отбрасываются; непрочитанные не перезаписываются. Каждый кадр несёт абсолютный индекс: при пропуске обработчик сбрасывает незавершённый цикл и заново ищет синхромаркеры. Счётчики PortAudio overflow/underflow отдельно показывают проблемы на уровне аудиопотока.

Детектор сопоставляет INPUT 1 с эталоном синхромаркера, порог нормированной корреляции — 0,75. Пакетный поиск сначала рассматривает один период и выбирает наилучшее совпадение, затем проверяет ожидаемые позиции с допуском ±512 отсчётов. Потоковый сборщик повторяет поиск при отсутствии маркера, сохраняет найденную позицию до получения полного цикла и оставляет хвост для следующего поиска. Инвертированная полярность маркера не поддерживается.

Обработка идёт полными циклами, поэтому изображение появляется с задержкой порядка одного–двух периодов. Очередь для SDL вмещает восемь готовых циклов. При её заполнении удаляется самый старый результат; память не растёт при медленном отображении. При выходе печатаются счётчики пропущенных кадров кольца, пропущенных результатов UI и событий PortAudio.

## Просмотр ранее сохранённых WAV

Запись диагностических WAV удалена. Живой режим обрабатывает вход только в памяти, не создаёт и не перезаписывает аудиофайлы. Ранее сохранённые файлы можно просматривать через replay.

Поддерживаются четыре канала, IEEE Float32, 48 кГц. Чтение сырых float-данных рассчитано на little-endian платформу. Для просмотра без аудиоустройства:

```bash
./build/acoustic_radar --replay capture.wav
```

Replay не открывает PortAudio и не воспроизводит звук. Готовые циклы отображаются один раз с интервалом 1000 мс; после последнего изображение остаётся до закрытия окна. ↑/↓ меняют лишь отображаемый диапазон, ←/→ в replay отключены.

Reader принимает формат прежних диагностических записей: стандартный 44-байтный заголовок с `fmt` размером 16 и следующим `data`, до 60 секунд. Произвольные WAV с дополнительными chunks не поддерживаются. Параметры возбуждения в WAV не сохраняются: replay использует текущие настройки программы, по умолчанию 1900–2900 Гц и отметку 250 мс.

Старая запись `diagnostics/input-check-2026-11-07.wav` и пример `diagnostics/spectrogram-preview.png`, если присутствуют, получены при прежнем периоде **600 мс**. Они не служат проверкой текущей синхронизации с периодом 1000 мс; для корректного replay нужен файл с текущим периодом циклов.

## Структура проекта

| Модуль | Назначение |
| --- | --- |
| `src/main.cpp` | SDL, клавиатура, выбор live/replay, порядок запуска и остановки |
| `audio.hpp/.cpp` | PortAudio, callback, статистика и передача входа в кольцо |
| `chirp.hpp/.cpp` | Генерация синхромаркера и возбуждения, атомарные настройки |
| `ring.hpp` | Кольцевой буфер с одним producer и одним consumer |
| `sync.hpp/.cpp` | Нормированная корреляция и поиск маркеров |
| `processing.hpp/.cpp` | Сборка непрерывного потока в циклы и очередь результатов |
| `spectrum.hpp/.cpp` | Окна Ханна, FFTW, амплитуды и временные координаты |
| `visualization.hpp/.cpp` | Накопление, палитра, оси и вывод SDL |
| `tests/` | Проверки DSP и потоковой обработки |

Публичные заголовки находятся в `include/acoustic_radar/`. SDL-объекты принадлежат основному потоку. Каждый анализатор владеет собственным FFTW-планом; экземпляры нельзя одновременно использовать из разных потоков.

## Проверки

```bash
ctest --test-dir build --output-on-failure
```

`spectrum_test` проверяет частоту и амплитуду известного синуса, временную координату, тишину, отбрасывание неполного цикла и синхронизацию. `streaming_test` проверяет ёмкость и порядок SPSC-кольца, конкурентную передачу, обработку синтетического потока дольше пяти секунд, поиск после начальной тишины и восстановление после разрыва. Тесты не включают звуковой выход и не требуют UR22C.

## Текущие ограничения

- Отражение бокала ещё нужно отделить экспериментально от отклика динамика и помещения. Наличие следа после chirp само по себе не доказывает резонанс бокала.
- При перестройке ось и линия длительности обновляются сразу, а генератор — в начале следующего цикла. Готовые результаты не содержат метаданных возбуждения, поэтому переходные циклы могут отображаться с новыми настройками оси.
- Масштаб яркости фиксирован; автоматической регулировки, выбора входного канала и настройки периода в UI нет.
- Записи в файлы нет; универсальное чтение WAV не реализовано.
- Ошибка `Steinberg UR22C not found` означает, что PortAudio не нашёл подходящее ALSA-устройство с нужным числом каналов. Успешная сборка и синтетические тесты не подтверждают аппаратную маршрутизацию.
